# Автономні сповіщення ДТЕК

`node src/notify.js` перевіряє одну адресу, надсилає сповіщення напряму через Telegram і не потребує Hermes або AI. `node src/monitor.js` залишається JSON CLI для ручної перевірки.

## Налаштування

Локально встановіть залежності (`npm ci` і `npx playwright install chromium`) та заповніть `.env` за `.env.example`. Для системного Chromium можна задати `CHROMIUM_PATH`.

Для GitHub Actions додайте repository secrets: `REGION`, `CITY`, `STREET`, `HOUSE`, `TELEGRAM_CHAT_ID` та `TELEGRAM_BOT_TOKEN`. `CITY` можна пропустити для `REGION=k`. Додайте бота в канал адміністратором із правом публікувати повідомлення. `TELEGRAM_CHAT_ID` — числовий ID каналу або `@username` публічного каналу.

Необов’язковий `DTEK_STATE_SECRET` — окремий випадковий секрет для шифрування стану. Якщо його не задано, ключ виводиться з токена бота. Окремий секрет дозволяє міняти токен без втрати доступу до стану. Зміна самого ключа потребує нової версії префікса кешу в workflow або окремої міграції стану.

## Запуски

Помістіть workflow `DTEK Telegram notifications` у default branch. Розклад UTC: `:00`, `:20`, `:40`; можливі затримки з боку GitHub. Після публікації можна вручну натиснути **Run workflow**. Перший успішний запуск для адреси створює baseline і нічого не надсилає. За відсутності конкретних змін наступні запуски також мовчать.

Стан для автономних сповіщень окремий від JSON CLI: `artifacts/alert-state/baseline.enc`. Workflow зберігає його в зашифрованому кеші, а не публікує графік чи адресу як артефакт. Якщо GitHub видалить кеш, наступний успішний запуск буде тихою ініціалізацією. При помилці ДТЕК або Telegram попередній стан зберігається для наступної спроби. Існуючий Hermes cron не змінюється; одночасний запуск обох автоматизацій може дублювати сповіщення.
