# Автономні сповіщення ДТЕК

Проєкт має два варіанти надсилання сповіщень:

- `node src/notify.js` — локальний запуск через Node.js/Playwright та `.env`.
- AWS Lambda — автономний запуск без Hermes і без GitHub Actions; EventBridge Scheduler викликає її за розкладом, стан зберігається в DynamoDB, повідомлення йдуть напряму в Telegram.

JSON CLI `node src/monitor.js` лишається окремим засобом ручної перевірки й сам повідомлень не надсилає.

## Локальний запуск

Встановіть залежності (`npm ci`, `npx playwright install chromium`) і заповніть `.env` за `.env.example`: `REGION`, `CITY`, `STREET`, `HOUSE`, `TELEGRAM_CHAT_ID`, `TELEGRAM_BOT_TOKEN`. `CITY` можна пропустити для `REGION=k`. Додайте бота в канал адміністратором із правом публікувати повідомлення. `TELEGRAM_CHAT_ID` — числовий ID каналу або `@username` публічного каналу.

Необов’язковий `DTEK_STATE_SECRET` — окремий випадковий секрет для шифрування локального baseline. Якщо його не задано, ключ виводиться з токена бота. Зміна ключа потребує міграції або нового baseline.

Локальний `node src/notify.js` використовує `artifacts/alert-state/baseline.enc`; не запускайте паралельно іншу копію з тією самою адресою, щоб уникнути дубльованих сповіщень.

## AWS Lambda

Налаштування стека, захищене передавання адреси й Telegram token, пакування ZIP, оновлення Lambda та перевірка розкладу описані в [AWS.md](AWS.md). AWS-варіант зберігає baseline у DynamoDB і не використовує локальний зашифрований кеш.

Розкладом керує EventBridge Scheduler у AWS (`:00`, `:20`, `:40` UTC). У репозиторії не залишено GitHub Actions workflows. Для деплою коду достатньо оновити ZIP Lambda; це саме собою не змінює розклад або стан DynamoDB.

Перший успішний запуск створює baseline і мовчить. Якщо ДТЕК або Telegram повертає помилку, попередній стан зберігається для наступної спроби.
