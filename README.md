# DTEK Monitor — JSON для Hermes

Разова команда на Node.js + Playwright. Відкриває сайт ДТЕК у headless Chromium,
вибирає населений пункт, вулицю й будинок, перехоплює AJAX `getHomeNum`, читає
погодинні дані сторінки й завершується з JSON у stdout.

Проєкт не надсилає повідомлень, не потребує токенів месенджерів, не зберігає
історію повідомлень і не запускає власний розклад перевірок. Hermes сам запускає
команду, обробляє JSON та вирішує, коли повідомляти користувача.

## Встановлення

Потрібні Node.js >= 22.15.1 і npm.

```sh
npm ci
npx playwright install chromium
```

На Linux для браузера також потрібні системні бібліотеки:

```sh
npx playwright install --with-deps chromium
```

## Адреса

Скопіюйте `.env.example` у `.env` в корені проєкту та заповніть адресу українською:

```dotenv
REGION=o
CITY="м. Одеса"
STREET="вул. ВАША ВУЛИЦЯ"
HOUSE="ВАШ БУДИНОК"
```

Використовуйте точні назви з підказок сайту. Префікси `м.`, `с.`, `вул.` можна
опустити, якщо назва однозначна. Неоднозначний вибір повертає помилку зі списком
кандидатів. Номери `5А` та `5/А` залишаються різними адресами.

Регіони: `o` — Одеська область, `k` — Київ, `kr` — Київська область,
`dn` — Дніпропетровська область, `d` — Донецька область. Для `k` місто можна
не вказувати. Структура форми перевірена для Одеського сайту; інші регіони
використовують відповідні сайти, але можуть змінювати форму незалежно.

`.env` читається відносно файлу проєкту незалежно від робочого каталогу Hermes.
Змінні середовища мають пріоритет над `.env`; аргументи CLI — над обома.

## Запуск

```sh
node src/monitor.js
node src/monitor.js --region o --city "м. Одеса" --street "вул. ВАША ВУЛИЦЯ" --house "5А"
npm --silent start
```

За замовчуванням браузер невидимий. `--headed` відкриває вікно для діагностики.
Звичайний браузер зберігає cookies поточної сесії, але headless не гарантує,
що сайт не покаже перевірку. Скрипт не розв'язує CAPTCHA та не приховує автоматизацію.

stdout завжди містить один JSON-об'єкт на рядок; діагностика й повторні спроби
йдуть у stderr. Для машинного виклику використовуйте `node`, або `npm --silent start`:
звичайний `npm start` додає власний текст перед JSON.

Код завершення `0` — отримано дані; `1` — помилка. За тимчасових помилок браузера
скрипт робить до двох повторних спроб із паузою 5 секунд. Тайм-аут навігації —
45 секунд, окремих дій — 15 секунд. Hermes варто дозволити команді до 5 хвилин.

## Контракт JSON, schemaVersion: 1

Успішна відповідь містить:

- `result: true`, `address`, `source`, `retrievedAt`, `timeZone: "Europe/Kyiv"`.
- `updatedAt.address`, `.daily`, `.weekly`: час оновлення відповідного джерела
  як на сайті. `retrievedAt` — час запиту в ISO UTC, а не час оновлення графіка.
- `scheduleDate`: дата `fact.today`, якщо сайт її надав; не обов'язково сьогодні.
- `flags`: прапорці видимості графіків з AJAX. Дані з вимкненим прапорцем не
  слід представляти користувачеві як чинний графік.
- `currentOutage.reported`: чи містить адресний запис повідомлення про відключення.
  `false` означає відсутність такого запису, а не підтверджену наявність світла.
  `currentOutage.data` — початковий запис саме цього будинку.
- `groups[]`: усі групи будинку, кожна з `id`, `name`, `daily[]`, `weekly[]`.
- `legend`: пояснення кодів з поточного сайту.
- `warnings[]`: застереження щодо кількох груп або відсутніх даних.
- `notices[]`: загальне інформаційне повідомлення сайту, якщо воно показане під час відкриття.
- `comparison`: результат порівняння з останнім успішним запуском для цієї адреси.

`daily[]` містить датований розклад із `fact`; `weekly[]` — прогноз за днями тижня
з `preset`, де `weekday: 1` — понеділок, `7` — неділя. Тижневий прогноз не є
підтвердженим графіком на конкретну дату. Порожній `daily` означає, що сайт не
опублікував датованих графіків; це не розклад без відключень.

Кожен день має `status: "available" | "partial" | "unavailable"` та `intervals[]`.
Інтервали задано в місцевому часі, початок включно, кінець виключно;
`24:00` — кінець дня. Приклад інтервалу:

```json
{ "start": "10:00", "end": "10:30", "status": "off", "sourceCode": "first" }
```

Статуси інтервалів:

| status         | Значення                                   |
| -------------- | ------------------------------------------ |
| `on`           | За графіком світло є                       |
| `off`          | За графіком світла немає                   |
| `possible_off` | Можливе відключення                        |
| `unknown`      | Відсутня комірка або невідомий код джерела |

Коди `first`/`second` і `mfirst`/`msecond` розділяються на два півгодинні інтервали.
Невідомі коди не перетворюються на `on`. Відсутній розклад має `intervals: []`.
Для кількох груп (`MULTIPLE_SUPPLY_GROUPS`) повертаються всі розклади:
скрипт не визначає, яка лінія живить конкретну квартиру.

Помилка також повертається JSON у stdout із кодом завершення `1`:

```json
{
  "schemaVersion": 1,
  "result": false,
  "error": {
    "code": "HOUSE_NOT_FOUND",
    "message": "House 999 not found.",
    "availableHouses": ["1", "2"]
  }
}
```

Основні коди: `INVALID_CONFIG`, `ADDRESS_NOT_FOUND`, `AMBIGUOUS_ADDRESS`,
`HOUSE_NOT_FOUND`, `INVALID_RESPONSE`, `INVALID_SCHEDULE`, `HTTP_ERROR`, `FETCH_FAILED`.
Якщо сайт повернув єдиний запис `-` для всієї вулиці, результат містить
`address.matchedHouse: "-"` і застереження `STREET_WIDE_RECORD`.

## Виклик із Hermes

### Збереження результату та виявлення змін

Кожен успішний запуск зберігає повний результат у `artifacts/state/<hash-адреси>.json`
відносно кореня проєкту. Для різних адрес використовуються окремі файли, незалежно
від поточного робочого каталогу. Ця папка вже виключена з git.

До повного JSON додається `comparison`:

```json
{
  "comparison": {
    "status": "unchanged",
    "changed": false,
    "previousRetrievedAt": "2026-10-18T12:00:00.000Z",
    "message": "Графік для цієї адреси не змінився."
  }
}
```

- `first_run`, `changed: null` — ще немає попереднього успішного результату.
- `changed`, `changed: true` — змінився розклад або інформація про відключення.
- `unchanged`, `changed: false` — суттєвих змін немає.

Порівнюються групи, дати добових графіків, дні тижневого прогнозу, часові інтервали,
їхні статуси, прапорці видимості та адресні дані про поточні відключення. Перестановка
груп або ключів JSON, інше розбиття однакових суміжних інтервалів, зміна часу запиту,
часу оновлення джерела, підписів або загального повідомлення сайту не вважаються
зміною графіка. Повний актуальний JSON повертається навіть без змін і зберігається
після кожного успішного запуску. Це порівняння запусків, а не підтвердження доставлення
повідомлення користувачу.

Помилки отримання даних не змінюють попередній результат. Файл спочатку записується
під тимчасовою назвою й потім замінюється цілком. Пошкоджений попередній файл або
недоступний для запису каталог повертають JSON-помилку `STATE_READ_FAILED` або
`STATE_WRITE_FAILED` і код завершення `1`, замість хибного `unchanged`.

Запускайте перевірки однієї адреси послідовно. У GitHub Actions runner тимчасовий:
для порівняння між різними workflow-запусками потрібно окремо переносити
`artifacts/state`. На постійній машині Hermes файли зберігаються між викликами.

### Команда запуску

На цьому Windows після заповнення `.env`:

```powershell
node "C:\Users\User\dtek-monitor\src\monitor.js"
```

На Linux/WSL встановіть залежності в середовищі Hermes та використайте абсолютний
шлях до його копії проєкту. Не переносіть Windows `node_modules` у Linux.

Інструкція для Hermes:

> Запусти DTEK Monitor командою `node <абсолютний шлях>/src/monitor.js` з тайм-аутом
> 5 хвилин. Прочитай JSON зі stdout та перевір код завершення. Якщо `result=false`,
> повідом про помилку; не використовуй її як свідчення відсутності відключень.
> За успіху перевір comparison, дати оновлення, flags і warnings. Якщо
> comparison.status = unchanged, графік не змінився з останнього успішного запуску;
> це не нова зміна, яку потрібно повторно надсилати. Для потрібної дати використовуй
> daily, а за його відсутності назви weekly лише прогнозом. Покажи всі групи,
> якщо їх декілька. Не визначай поточну наявність світла з відсутності повідомлення
> про аварію. Надсилання повідомлень виконуй власними засобами.

## Перевірки та GitHub Actions

```sh
npm test
```

Тести не звертаються до ДТЕК: перевіряють декодування півгодин, відсутніх даних,
кількох груп, адрес і формату помилок. Живий запуск потребує доступного сайту.

Workflow `monitor.yml` запускається вручну та зберігає `schedule.json` як artifact.
Він використовує адресні secrets `REGION`, `CITY`, `STREET`, `HOUSE`. Автоматичний
таймер, надсилання повідомлень і запис стану в git прибрані.
